## Decisions

One substantive tool resource per dumbbell, slopegraph and small-multiples intent, with working import, data table, export, definition, decision guidance and limitations. Do not create separate barbell, before-after, trellis or panel-chart synonym pages. Keep annotated line/bar work on the existing maker URLs. The editorial hub is a collection/navigation resource, not an asserted high-volume “news chart maker” opportunity. Waffle is deferred pending evidence; it is not necessary for this approved initial newsroom workflow.

Examples must have pinned primary data, source/license/date, exact accessible values, explicit transformations, an original interpretation and editable project files. Prefer a substantive multi-view worked resource over separate near-duplicate pages for each view of the same data. No current-news feed or automated factual headlines.

## Validation gates

Native ECharts shared preview/export; data-anchored notes; shared small-multiple scales; signed values; no implicit aggregation or missing-to-zero replacement. Test project validation/round-trip, SVG/HTML escaping, numeric conventions, exports and imports in browser. Static content, canonicals, schema, internal links and sitemap are build checked. Plausible receives fixed action/type/format identifiers, no user data or private filenames. No ranking, citation or traffic guarantees.

Competition is already strong: Datawrapper offers free PNG and publishing/embeds (https://www.datawrapper.de/pricing); Flourish has a dedicated newsroom product (https://flourish.studio/solutions/newsrooms/). The practical contribution is a free, local, open-source publishing package with transparent methods and editable files, whose usefulness must be measured.
